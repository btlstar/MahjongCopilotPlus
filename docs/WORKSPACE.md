# 开发目录与启动入口

## 唯一工作目录

后续只维护 GitHub Desktop 管理的 `MahjongCopilotPlus` 克隆目录。在这里 Pull、修改源码、查看 Git 差异并运行根目录 `start.bat`。不要再向另一个下载副本镜像源码。

旧 `MahjongCopilot-max-main` 下载目录曾用于开发和依赖安装，之后作为本机历史目录保留。它根目录的 `MahjongCopilot.exe` 是独立的旧构建，源码更新不会更新这个文件。

## 启动与依赖

`start.bat` 使用工作目录中的 `venv/Scripts/pythonw.exe` 运行同目录 `desktop_entry.py`。它不搜索历史 exe，也不负责创建虚拟环境、安装依赖或下载 Chromium。正常安装步骤见[安装说明](INSTALL.md)。

本机可临时用目录联接让 `venv/` 复用已有环境；这只是本机配置，不能随源码分发。联接依赖的原环境目录暂时不能删除。如需彻底清理旧下载目录，先在主工作目录按安装说明建立独立环境，再确认启动正常。不要直接移动虚拟环境或复制整个历史 `_internal/`。

## 哪些内容会更新

| 内容 | 处理方式 |
| --- | --- |
| 克隆目录的源码、文档、`start.bat` | 后续唯一维护对象 |
| `venv/`、Chromium、可选原生库 | 本机依赖，不随源码提交；依赖变化时单独更新 |
| `settings.json`、装扮设置、浏览器数据、证书 | 本机私人数据，不跨目录自动同步，也不加入 Git |
| `build/`、`dist/`、旧 exe／便携包 | 历史产物，后续不再打包更新 |
| 旧下载目录的源码 | 历史副本，后续不再同步 |

已有 exe 的设置与源码工作树设置是分开的；需要保留时按[升级说明](UPGRADING.md)手动迁移。历史文件和私人配置不因变更分发方式而自动删除。
