# 开发目录与启动入口

## 唯一工作目录

后续只维护 GitHub Desktop 管理的 `MahjongCopilotPlus` 克隆目录。在这里 Pull、修改源码、查看 Git 差异并运行根目录 `start.bat`。不要再向另一个下载副本镜像源码。

旧 `MahjongCopilot-max-main` 下载目录曾用于开发和依赖安装。完成迁移、依赖与私人资料校验后，可以归档并删除旧下载副本、历史便携包和对应压缩包。历史 exe 不会随当前源码更新，不应再作为启动入口；若旧路径保留为目录联接，它只指向新目录，不是另一份源码。

## 启动与依赖

`start.bat` 使用工作目录中的 `venv/Scripts/pythonw.exe` 运行同目录 `desktop_entry.py`。它不搜索历史 exe，也不负责创建虚拟环境、安装依赖或下载 Chromium。正常安装步骤见[安装说明](INSTALL.md)。

## 迁移到另一磁盘

1. 关闭程序、游戏浏览器以及正在进行的 Git 写入操作，复制完整仓库，包括隐藏的 `.git`、未提交文件和本机私人资料。
2. 在新位置重新创建 `venv` 并安装运行依赖；不要直接移动旧虚拟环境。浏览器安装位置、模型和可选原生库也需核对。
3. 对比 Git HEAD、暂存区、未提交差异和私人文件，运行依赖检查、受影响的回归及 BAT 启动检查。
4. 使用 GitHub Desktop 的“添加本地仓库”，或官方 `github <新路径>` 命令打开新位置。原目录若保留为联接，只是兼容入口，不是另一份源码；以后以新位置为准。
5. 验证后再清理旧环境、构建产物和旧副本；私人资料的唯一副本不能当作缓存删除。完整备份保留在仓库之外，避免误提交。

机器上的实际路径和兼容入口记录在被 Git 忽略的 `WORKSPACE.local.md`；公开文档不携带用户名、个人路径或凭据。

## 哪些内容会更新

| 内容 | 处理方式 |
| --- | --- |
| 克隆目录的源码、文档、`start.bat` | 后续唯一维护对象 |
| `venv/`、Chromium、可选原生库 | 本机依赖，不随源码提交；依赖变化时单独更新 |
| `settings.json`、装扮设置、浏览器数据、证书 | 本机私人数据，不跨目录自动同步，也不加入 Git |
| `build/`、`dist/`、旧 exe／便携包 | 历史产物，后续不再打包更新 |
| 旧下载目录的源码与压缩包 | 不再同步；完成迁移与私人资料校验后可归档清理 |

已有 exe 的设置与源码工作树设置是分开的；需要保留时按[升级说明](UPGRADING.md)手动迁移。历史文件和私人配置不因变更分发方式而自动删除。
